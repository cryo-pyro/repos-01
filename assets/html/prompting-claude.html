The core workflow

Three words and an image

The entire workflow is this: upload the image into the chat, type what you want, optionally name the aesthetic register. That's it. Here's what a complete prompt looks like:

# Minimal — always works
↗ Translate this into interactive HTML

# With aesthetic direction — gets better results
↗ Translate this into interactive HTML, dark industrial like the Nvidia piece

# With specific interactions — best results
↗ Translate this into interactive HTML. Make the bar chart hoverable with tooltips.
Add scroll reveals. [aesthetic register]

# With raw data attached — highest fidelity
↗ Translate this chart into interactive HTML.
Numbers: Nvidia 80%, Google 7%, AMD 6% ...

The image gives me layout, hierarchy, and visual language. The prompt tells me what should move. The register tells me the emotional tone. Together they are complete instructions.

Four tips for best results

What to say and how to say it

01
Name what should move
I'll make judgment calls if you don't specify — and they'll usually be good. But "make the bar chart interactive" or "add hover states to the table rows" gives me an explicit target. The more specific the interaction, the closer the first draft lands.
02
Name the register
One sentence replaces three rounds of revision. "Dark industrial like the Nvidia piece" or "clean editorial like the sports stats doc" orients the typography, color, and motion choices immediately. Without it I invent something — which may or may not be what you wanted.
03
Paste the numbers
Chart images compress. Small labels at low resolution become ambiguous. If the data is important and you have it as text or CSV, paste it alongside the image. I'll use your exact numbers rather than approximating from pixels. Always worth a sanity-check on the output either way.
04
Context accelerates everything
If the image is from a report, name it. If it's a dashboard mockup, say what data it should show. If it's a wireframe, say who uses it. Context about purpose produces interfaces that feel designed for something, not just translated from something.
What I do best

Image types and what they become

Image type What it becomes Fidelity
Static bar / line chart Live Chart.js with tooltips, hover highlights, animated on-load draws Best
Data table / spreadsheet Sortable, filterable HTML table with row hover states and sticky headers Best
Infographic / diagram Animated SVG or sectioned HTML with scroll reveals and clickable nodes Best
Dashboard screenshot Full interactive layout: working charts, stat cards, filter controls Best
Wireframe / sketch Actual built UI — inputs, buttons, navigation, hover states Good
Report page (text-heavy) Typeset HTML with section structure, callouts, pull quotes, footnotes Good
Dense spreadsheet at low res Reconstructed from visible data — may miss small labels Verify numbers
Scanned handwriting / sketch Interpreted, not traced — I'll produce the structure I infer Describe intent
The one real limitation: very dense small text in low-resolution images — spreadsheet screenshots, compressed PDFs rendered as images — can produce ambiguous labels. I'll do my best but will note when I'm uncertain. The fix is always to paste the numbers alongside the image.

Canonical case study

The Nvidia piece: from .png to live page

↗ Live reference — Ukubona Compute Intelligence abikesa.github.io/repos-00/assets/html/nvidia-winning.html

The original document was a plain HTML page with a broken <img> tag pointing to a missing ../img/nvidia-winning.png — a static chart that wasn't even loading. The prompt was: "Upgrade this one too. Majorly."

The output replaced the broken image with a live Chart.js area chart built from the data in the surrounding prose, added a market share grid with proportional bars, reconstructed the full analysis with the Ukubona pentadic framework applied to compute infrastructure, and wrapped it in a dark industrial aesthetic with Barlow Condensed + IBM Plex Mono typography, a scanline hero animation, and a giant "NVDA" watermark behind the title.

That's the whole workflow in one example: one broken image + three words of instruction + an aesthetic reference = a production-grade interactive analysis page.

What made it work

The content had internal density — the Ukubona pentadic framework, the 70% leakage analogy, the gradient sovereignty language. Rich ideas produce rich interfaces. The design rose to meet the content because the content gave it something to carry. The aesthetic followed from the subject: compute infrastructure, hardware monopoly, industrial scale. Barlow Condensed and scanlines are the visual language of that subject. The font choice wasn't decorative — it was argumentative.
