Ukubona Digital Twin · Deployment Playbook

From setup.sh
to live twin.
Zero code written.

You didn't install Python. You didn't install React. You didn't write a single line of backend code. You ran one script and got a live, cloud-deployed, eigen-analysing digital twin. This is the playbook for how that happened — and how to do it again for any client in under 10 minutes.

The Mac was just a messenger. It ran the script, which talked to GitHub's API and Render's API. All the heavy lifting — installing Python 3.11, compiling pandas, building React — happened on Render's servers in the cloud. Your machine never needed any of it.

And yes — you can do this entirely from VS Code in the browser on github.dev. Open any repo at github.com, press . (period key), VS Code opens in browser. Edit files. Commit. Render auto-deploys. You never even need a terminal.

4

GitHub push (automatic)

The script calls GitHub's API to create the private repo, then pushes all files. Your Mac needs git installed (it comes with Xcode Command Line Tools — already there on most Macs). That's the only local dependency. 

# The script does all of this for you:
git init
git add .
git commit -m "Strata Stone Digital Twin — 93 variables"
git branch -M main
git remote add origin https://TOKEN@github.com/USER/REPO.git
git push -u origin main --force

Result: https://github.com/your-username/your-repo — private, live, all files present.

5

Render — Backend (1 manual step)

Render's Blueprint API is unreliable for services that already exist. So we do the backend manually — takes 90 seconds. Go to dashboard.render.com → New + → Web Service.

Name{REPO_NAME}-api
EnvironmentPython
Branchmain
Build Commandpip install -r backend/requirements.txt
Start Commandcd backend && gunicorn main:app -w 2 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:$PORT

Add environment variables:

PYTHON_VERSION3.11.8
PROJECT_NAMEyour project name
LOCATIONyour location
Why not rootDir: backend? Render ignores rootDir for build/start commands on web services — it only works for static sites. So we use explicit paths: backend/requirements.txt and cd backend &&. Hard-won lesson from 3 failed deploys.
Why PYTHON_VERSION=3.11.8? Render defaults to Python 3.14 (latest). pandas 2.2.x has no pre-built wheel for 3.14 yet — so it tries to compile from source and times out. Pinning to 3.11.8 gets the pre-built wheel and installs in seconds.
6

Render — Frontend (1 manual step)

Same Render dashboard → New + → Static Site. Connect the same repo.

Name{REPO_NAME}-ui
Branchmain
Root Directoryfrontend
Build Commandnpm install && npm run build
Publish Dirbuild

Add environment variable:

REACT_APP_API_URLhttps://{REPO_NAME}-api.onrender.com
Why does rootDir work here but not for the backend? Static sites are different — Render uses rootDir to set the working directory for the whole build. Web services don't honour it the same way. Inconsistent, annoying, now documented.

Iterate — from anywhere

Once the repo exists, you never need to run setup.sh again. Every push to main triggers an automatic redeploy on Render. 

# From your Mac terminal:
git add .
git commit -m "update: add real leakage data"
git push
# Render auto-redeploys in ~3 minutes
From github.dev (no terminal needed at all):
Go to your repo on github.com. Press the . (period) key. VS Code opens in the browser. Edit any file. Click the Source Control icon. Write a commit message. Click ✓ Commit & Push. Render sees the push and redeploys automatically. You never opened a terminal.

For your next client — new folder, new setup.sh, different repo name and project name. 10 minutes from empty folder to live twin. Every time.
